# Draft Causality Protocol v1.0

- 상태: `LOCKED_PROTOCOL / RESULTS_R09_HOLD`
- 목적: 경기 결과가 바뀌었는데 유명 선수와 드래프트 역사를 억지로 원상복구하는 오류를 막는다.
- 적용: 2018 NBA Draft 이후 모든 NBA 드래프트·트레이드·보호픽
- 원고 게이트: `CLOSED`

## 핵심 원칙

드래프트의 실제 결과는 보존 목표가 아니다. **입력이 같으면 실제 결과를 유지하고, 입력이 바뀌면 규정과 팀 판단에 따라 결과도 바꾼다.** 유명 선수의 실제 행선지도 예외가 아니다.

## 계산 사슬

```text
선수 투입
→ 경기별 출전시간·포제션 재배분
→ 바뀐 경기의 승패 확정
→ 시즌 승수·순위·타이브레이커 재계산
→ 로터리 시드·확률 재계산
→ 픽 보호·양도·스왑 조건 판정
→ 드래프트 순서 확정
→ 해당 순번부터 팀별 보드·필요·거래 재판정
→ 계약·로스터·다음 시즌으로 파급
```

중간 단계를 건너뛰고 작가가 원하는 팀에 선수를 배치하지 않는다.

## 1. 경기와 순위

1. 주인공·라이벌이 출전하거나 그들의 로테이션 파급이 닿은 경기는 접촉 경기로 기록한다.
2. 접촉 경기의 승패는 실제 결과를 자동 보존하지 않는다.
3. 비접촉 경기는 실제 결과를 유지한다. 다만 부상·트레이드·휴식처럼 앞선 파급이 선발명단에 닿으면 접촉 경기로 승격한다.
4. 정규시즌 종료 뒤 승수, 콘퍼런스 순위, 플레이오프 진출, 공식 타이브레이커를 해당 시즌 규정으로 다시 계산한다.
5. 한 경기 변화가 다른 팀의 순위·플레이오프·로터리 시드를 바꾸면 그 팀도 하류 사건 원장에 포함한다.

## 2. 로터리

1. 해당 드래프트 연도의 실제 로터리 제도와 팀별 확률을 사용한다.
2. 재계산 뒤 로터리 참가팀과 시드가 실제와 모두 같으면 실제 추첨 결과를 외부 확률 사건으로 유지한다.
3. 참가팀·시드·확률 중 하나라도 달라지면 실제 추첨 결과를 강제하지 않고 재추첨한다.
4. 재추첨은 결과를 본 뒤 고르지 않는다. R09 시뮬레이터에 공개된 고정 seed와 알고리즘을 먼저 기록하고 실행한다.
5. seed 규칙은 `SHA-256("first-rebound|nba-lottery|{draft_year}|v1")`로 잠근다. 정확한 조합 배분·중복 추첨 처리는 해당 연도 공식 절차를 구현한다.
6. 로터리 결과가 크게 달라져도 되돌리지 않는다. 바뀐 시드에서 나온 합법적 결과는 정본 후보가 된다.

## 3. 보호픽·양도·스왑

1. 픽의 원소유 팀, 현재 보유 팀, 보호 범위, 양도 연도, 소멸·전환 조건을 거래별로 기록한다.
2. 재추첨 순번이 보호 범위에 들어가면 실제 역사와 달리 픽이 남을 수 있다.
3. 보호 범위를 벗어나면 실제와 달리 픽이 양도될 수 있다.
4. 그 결과 뒤 연도 픽까지 바뀌면 다음 드래프트 원장에 연결한다.
5. 거래를 유명해서 보존하지 않는다. 다만 거래 당시 입력이 바뀌지 않았다면 실제 거래를 유지한다.

## 4. 팀별 지명

1. 확정된 순서대로 한 픽씩 진행한다.
2. 각 팀은 남은 선수, 당시 프런트·감독, 포지션 필요, 의료정보, 계약·로스터 상황을 기준으로 최소 세 후보를 비교한다.
3. 실제 선택 선수가 이미 지명됐거나 새 선수가 팀 보드 상위에 들어오면 해당 픽을 재판정한다.
4. 한 선수가 밀렸다고 이후 선수를 기계적으로 한 칸씩 미루지 않는다. 각 팀이 다시 선택한다.
5. 변경은 인과가 닿는 동안 계속한다. 결과적으로 후반 보드 전체가 바뀌더라도 허용한다.
6. 실제 드래프트 선수가 미지명되면 투웨이·캠프·해외 계약까지 후속 경로를 기록한다. 선수를 삭제하지 않는다.

### 계산량 통제

드래프트 전체를 같은 깊이로 조사하지 않는다. **원장은 전수, 심층 검토는 변화 지점** 원칙을 쓴다.

1. 2018은 주인공 지명 뒤인 30~60순위만 전수 스캔한다. 1~29순위는 시간상 선행사건이라 다시 열지 않는다.
2. 각 픽의 1차 스캔은 실제 선택, 새로 남은 Spellman/연쇄 이탈자, 당시 보드의 비교 후보 한 명으로 제한한다.
3. 실제 선택 선수가 여전히 남아 있고, 새 후보가 당시 필요·보드에서 명백히 앞서지 않으면 `UNCHANGED`로 짧게 통과한다.
4. 새 후보가 실제 선택을 밀어낼 가능성이 있거나 실제 선택 선수가 이미 사라졌을 때만 `CHANGED/CASCADE` 심층 비교를 연다.
5. 한 선수가 새 팀에서 선택되면 그 선수의 실제 후속 경로와 새 팀의 로스터·분·거래 파급만 추적한다.
6. 남은 픽은 원장상 계속 확인하지만, 변화가 없는 팀마다 장문의 관계·커리어 조사를 붙이지 않는다.

이 방식은 합리성을 줄이지 않으면서 31개 픽을 관리 가능한 감사 작업으로 제한한다.

## 5. 연도별 적용 경계

### 2018 Draft

- Atlanta의 30순위 이전에 완료된 1~29순위와 Doncic–Young 거래는 주인공 지명보다 시간상 앞서므로 유지한다.
- 30순위에서 주인공이 Omari Spellman을 대체한다.
- 30~60순위는 Spellman을 포함해 순차 재판정한다. `Spellman만 임의로 미지명 처리`하거나 `31번부터 전원 한 칸 이동`하지 않는다.

### 2019 Draft

- Atlanta의 2018-19 재계산 승수로 자체 로터리 시드와 확률을 다시 구한다.
- Dallas에서 받은 보호 1라운드 픽은 Dallas의 재계산 승수·로터리·보호조건으로 양도 여부와 정확한 순번을 다시 판정한다.
- 실제 Atlanta 8·10순위는 기준선이지 보장값이 아니다.

### 2020 Draft

- 라이벌은 `실제 1순위 확정`이 아니라 `1순위 후보 수준`이다.
- 2019-20 NBA 순위·로터리·픽 소유권을 먼저 확정한 뒤, 라이벌의 ACL 의료자료·Gonzaga 복귀·팬데믹 스카우팅 제약을 팀별로 평가한다.
- 라이벌이 1순위가 되면 Anthony Edwards 이하 보드도 다시 계산한다. 실제 상위 3명을 보존하기 위해 라이벌을 억지로 내리지 않는다.
- 반대로 팀 필요와 의료 불확실성 때문에 순번이 내려가도 `1순위급 평가`와 모순으로 보지 않는다.

## 금지

- 유명 선수의 실제 팀을 지키려고 바뀐 승수를 무시하기
- 실제 로터리 순번을 먼저 정한 뒤 승패를 끼워 맞추기
- 보호픽 조건을 생략하고 실제 양도만 복사하기
- 한 픽 변화 뒤 모든 선수를 자동으로 한 칸씩 이동시키기
- 주인공이 접촉하지 않은 과거 픽까지 소급 변경하기
- 시뮬레이션 결과가 마음에 들지 않는다는 이유로 seed를 다시 뽑기

## R09 산출물

- 시즌별 경기 원장과 재계산 최종 순위표
- 로터리 참가팀·시드·확률·seed·실행 로그
- 픽 소유권·보호조건 원장
- 실제 보드와 대안 보드의 순번별 비교표
- 변경 선수의 계약·로스터 후속 경로
- 다음 시즌으로 넘어가는 승수·픽·계약 나비효과 링크

## R09 실행 상태 — Atlanta baseline + 2018 picks 30-60 v0.2

- 82경기·실제 29승 53패·9,294득점·연장 포함 19,855 선수분 기준선은 `PASS`다.
- 주인공의 1차 출전시간 상한은 실제 30순위 Omari Spellman의 805분이다.
- 주인공이 결장해도 Spellman 부재가 남으므로 82경기 모두 최소 `ROSTER` 접촉이다.
- 경기별 player-game 분·가용성·피로와 대체 승패는 아직 `HOLD`다.
- 2018 Draft 30~60 전수 스캔 결과는 27개 유지, 4개 변경이다. Spellman은 San Antonio 49번, 밀려난 Metu는 Dallas 56번, Spalding은 Denver 58번으로 이동한다.
- Thomas Welsh는 미지명 뒤 실제와 같은 Denver 투웨이 역할 후보지만 계약·슬롯 검산 전 `PROVISIONAL_ROLE_PRESERVED`다.
- Spellman의 새 팀은 해결됐으나 Spurs 2018-19 분·승패 파급이 닫히기 전 2019 standings·lottery는 `FINAL` 금지다.
- 상세 원장과 감사 게이트는 `simulation/ATLANTA_2018_19_CAUSALITY_LEDGER.md` 및 `.xlsx`가 권위다.
- 후반 보드의 선택 근거는 `simulation/2018_DRAFT_30_60_ALTERNATE_BOARD.md`가 권위다.
