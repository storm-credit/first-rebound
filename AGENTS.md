# Codex continuation and author decision rule

User instruction recorded 2026-09-27: continue `first-rebound` repository work in Codex through the already approved scope. Do not send the user back to another chat after every season. Bring an important canon-changing choice to the author only when evidence and comparable options are ready for a decision.

## At the start of each continuation

1. Read `PROJECT_STATE.md`, `canon/PROJECT_FREEZE.md`, `control/DESIGN_GATE.md`, and `design/WORLD_BIBLE_COMPLETION_ROADMAP.md` from the latest `main`. Check recent PRs/commits and the working tree. Use these files to recover the actual checkpoint; do not restart the plan from a remembered older season.
2. Preserve completed work and prior author approvals. Separate **fact / inference / candidate / author locked** in research and simulations. A conditional recommendation is not an author lock.
3. Keep `PROJECT_FREEZE v0.30 PARTIAL` and design/manuscript gate `CLOSED` unless a later explicit author instruction changes them. Do not draft manuscript while the gate is closed.
4. Continue safe, authorized research, season/career architecture, repository edits, cross-file continuity checks, and the existing PR → `main` flow without requesting the same approval again. Use `control/RESEARCH_VERIFICATION_LAYER_V2.md` to distinguish source collection, analysis, repository checks, independent rebuttal, and blind-spot review; record tools that fail or were not run honestly.

## Escalate only a consequential author choice

Stop promotion to canon and notify the user when the next step would choose among materially different long-term outcomes, for example: protagonist franchise retention versus a move; the year of MVP-level growth; championships and their league-wide butterfly effects; or a transaction/contract/health event that changes the approved direction. Do not interrupt for a routine source lookup, mechanical correction, or each season boundary. Continue independent work while that choice is pending.

Before notifying, prepare a concise decision packet: the exact choice and why it is now necessary; 2–4 mutually exclusive options; historical evidence with provenance; roster, minutes, salary/CBA, draft, playoff, character and later-season costs as applicable; a recommended option and uncertainty; the files and gates that would change. Keep all options `CANDIDATE` until the author selects one. Do not silently infer author approval from a request to continue.

When a choice is made, record the author decision in the repository, propagate it through timeline/Context Pack/dependencies, run relevant mechanical and independent checks, and merge by PR. Notify again at completion or the next consequential choice. In every work report, show the seven-row project progress table and the count of unfinished major groups from the roadmap. Do not turn unequal groups into a percentage or invent an ETA.
